# 마음의 향기 타로 — notes for Claude sessions

Classroom web app for Korean students (초3–중3): emotion color → topic → draw 3 tarot cards → reading + up to 3 AI follow-up questions → scent recommendation (then an offline blind smell test).
The owner (학원 원장님) is not a developer. Write owner-facing text in plain Korean, student-facing copy in short 해요체.

## Stack (no build step — keep it that way)
- Static files served by Vercel project `ai-smell`, deployed from GitHub. `api/*.js` = Vercel serverless functions (CommonJS).
- `index.html` — app shell: CSS + the inline app script. Load order: `content.js` → `safety.js` → `prompts.js` → `reading.js` → inline script.
- `content.js` — **all lesson content**: cards (`ko`, `img`, `up`, `down`, `scent`, `hidden`, polarity flags `heavyUp`/`lightDown`/`bright`, `notLiteral` reassurance text on 죽음·탑; picture-story fields on **every** card incl. hidden: `story` (2–3 sentences, 해요체), `look` (2–3 `[symbol, meaning]` pairs), `ask` (one short '나라면?' question, must pass `Safety.check`)), topics, colors, roles, `COLOR_MEANING` (two-sided, 해요체), `TOPIC_HOOK` (one line per topic), `ROLE_TAIL` (3+ tails per role), moods/scents (`MOOD_DESC`, `DEFAULT_SCENTS` describe the smell, never an effect), `SMELL_QUESTIONS` (fallback 'smell and think' questions on scent cards), `CHAT_CHIPS` (fallback question chips, ≤25 chars), `COVER_TITLE`, image paths. UMD: `window.CONTENT` in the browser, `module.exports` for `api/*.js` (`require('../content.js')`) and tests.
- `safety.js` — child-safety check, shared by app and API. `Safety.check(text)` → `{cat:'self_harm'|'sexual'|'abuse'|'bullying'|'danger'}` or `null` (normalizes: NFC, lowercase, strips spaces/punctuation/zero-width, collapses 3+ repeats; a `SCRUB` list blanks benign look-alikes first — whole words only: 과자 살래 / 혼자 살아 / 한자 해석 / 수학 대회 / 때려치우다·때려잡다 / 정답·공·100점 맞았어 / 맞는 선물 / 트램펄린에서 뛰어내렸어 / 칼로 찌르는 그림 / ○○ 예방 교육 …). Bare `자살`/`자해` always fire except before a few syllables that clearly mean something else (자살골, 자 살래?, 놀자 해서); slang (뒤지고 싶다, 삥, 빵셔틀, 뒷담), English (`i want to die`, `kill myself`, `kms`, `suicide`, `self harm`) and actor…gap…touch/hit phrasings are covered. Also `redact()` (phone/email/6+ digit runs), `HELP` / `HELP_TEXT` (help-card copy + 1388/109/117/112), `MARKER` `[도움필요]`, `hasMarker()` (bracketed anywhere, or a bracketless `도움필요` at the very start followed by a space/punctuation). **No regex lookbehind** (older iPad Safari can't parse it; a test enforces this).
- `prompts.js` — the only place for AI prompts and for checking AI output: `SAFETY_BLOCK` (always first in every system prompt), `QA_SYSTEM`, `firstTurn(ctx, q)`, `buildMessages(ctx, history, q)`, `ASK_LIMIT`, `HISTORY_MAX`, `QA_MAX_TOKENS`. `ctx = {topic, color, cards:[{ko, rev}], reading?}`; card meanings are looked up in content.js. Used by index.html (`window.Prompts`) and api/ask.js (`require('../prompts.js')`).
  AI reading: `READING_SYSTEM` (deterministic: safety block + rules + 4-section format + one example with visible cards + color dictionary + dictionary of **all** cards incl. hidden, sorted by code point — never put dates/randomness/`localeCompare` in it; a test checks it is byte-identical across builds and in a browser context, so prompt caching works), `buildReadingUser({color, topic, cards})` (the only per-student part; never the note), `READING_TITLES` (= roles + '세 카드의 흐름'), `READING_MAX_TOKENS` 1200, `parseReading(text)` → `[{head, body}]` (works mid-stream; lines starting with `■`), `readingOk(secs, cards)` (exactly 4, titles in order, card name + 정/역방향 match, bodies non-empty), `FORBIDDEN` / `badReading(text)` (fortune-telling/diagnosis words; '운명의 수레바퀴' allowed) and `badSoFar(text)` for mid-stream checks (ignores a trailing, not-yet-complete '운명의 수레바퀴' — otherwise every reading with that card failed whenever a text chunk ended at '운명'). Extras: `EXTRAS_SYSTEM`, `buildExtrasUser(ctx, scents)`, `EXTRAS_MAX_TOKENS` 500, `parseExtras(text, names)` → `{scents:{name:{reason?, ask?}}, questions:[≤3]}` (`firstJson()` scans each `{` with a brace-depth counter that skips quoted text and takes the first object with a `scents`/`questions` array, so stray `{예시}` prose around the JSON is fine; every field validated: name must exactly match an app-picked scent, reason ≤60, question ≤25, no Safety hit/marker/forbidden word). `studentTokens()` → rough `{input, output}` for one student (reading + extras + 3 questions, 1 char ≈ 1 token) for the Settings price labels.
- `reading.js` — pure draw/reading logic (UMD: `window.Reading` + `module.exports`, browser + tests only). `hasJong(w)` / `josa(w,a,b)` (returns `w`+particle; skips closing quotes; digits read Sino-Korean), `nth(i)` → 첫/두/세 번째, `FAN_MAX`, `REV_CHANCE`, `makeDeck(n=FAN_MAX)` (never more than `FAN_MAX` or the visible pool; the app passes 15 on phones ≤700px via `fanSize()`), `drawOne(deck,i,draw)` → `{...card, rev}` (falls back to deckPool if the slot is drawn/hidden), `heavy(card)`, `FLOW` + `combine(a,b,c)` (5 summaries, all reachable), `make({color,topic,draw,hasNote})` → reading HTML, `pickScents(draw,lib)` → 3 scents `{name,mood,desc,from}` (round-robin: one per card; `from` = card slot 0/1/2 or null), `localAnswer(q,n,{draw,topic,scents})` (keyword buckets + rotation by `n` = number of earlier local answers; a card's own story question (`ask`, also as '카드 이름 카드: ask') is answered about that card first; a scary question names the asked 죽음/탑 card; future questions get "카드는 미래를 맞히지 않아요"; family/friend talk gets thanks first).
- `api/ask.js` — optional server path for follow-up questions. Works only if `ANTHROPIC_API_KEY` is set in Vercel (today it is NOT → returns `NO_KEY`). The main AI path is the teacher's device key (Settings, stored in localStorage) calling `api.anthropic.com` directly — owner's explicit choice, do not remove.
  Body: `{topic, color, cards:[{ko,rev}]×3, question, history:[{role:'user'|'assistant', content}]}` (history = earlier AI-answered Q/A only, alternating, ≤6, user ≤300 / assistant ≤1500 chars). Order: 405 → same-origin (403) → 8KB cap in UTF-8 bytes (413) → safety (`SAFETY` + help text, no upstream call) → strict validation (400) → `LIMIT` → `NO_KEY` → per-IP limit (`RATE`, 60 AI calls/min per warm instance, `x-real-ip`/`x-forwarded-for`) → upstream with a 15s timeout. The endpoint is stateless: `LIMIT` only counts the history the client sends, and the in-memory limit is per instance — **before ever setting `ANTHROPIC_API_KEY`, also add a Vercel Firewall rate-limit rule on `/api/ask` (generous, a class shares one IP) and a low monthly spend limit in console.anthropic.com.** Reasons: `OK NO_KEY LIMIT RATE BUDGET TIMEOUT SAFETY API_ERROR`. Never trust client reading/meaning text: the first turn is rebuilt from content.js.
- Models: only `claude-haiku-4-5` (default) and `claude-sonnet-5-5`. `normModel()` in index.html maps any saved legacy value to one of them. Haiku: no `thinking` field. Sonnet: `thinking:{type:'between_tools'}` + header `anthropic-beta: server-side-fallback-2026-07-01` + body `fallbacks:'default'`; on HTTP 400 (or a network error) it retries once without the beta header and `fallbacks` (`claudeFetch()`), then remembers that (`noBeta`) so later calls on the page go straight without them. Every device-key system prompt (reading, chat, extras) is sent as a `cached()` text block with `cache_control` (Sonnet 5.5 caches from 512 tokens; Haiku 4.5 needs 4096, so there it silently does nothing). Price labels: `PRICE` (USD per 1M in/out: Haiku 1/5, Sonnet 2/10) × `Prompts.studentTokens()` × `WON_PER_USD` 1400 → `won(model)` ('학생 1명 약 ○원', rounded to 5원).
- `vercel.json` — function config, security headers (CSP needs `'unsafe-inline'` for the inline script and `onclick` attributes; `connect-src` includes `https://api.anthropic.com` for the device-key path), 1-week cache for `/cards/*` and `/fonts/*`. The CSP blocks Vercel's preview toolbar (`vercel.live`) — harmless for the app; `tests/smoke.cjs` ignores those console errors. To silence it on previews, set `VERCEL_PREVIEW_FEEDBACK_ENABLED=0` in the project's Preview environment (don't widen the production CSP).
- `.vercelignore` — `tests/`, `*.md`, `*.zip`, `.github/` are not deployed. Never ignore `content.js` / `safety.js` / `prompts.js` (the API bundles them).

## Release process (반영 절차)
1. Work on a branch; never commit straight to `main`.
2. Push the branch → Vercel builds a **Preview URL**. Run the smoke test against it.
3. Send the owner the preview URL. Merge to `main` (= live site) **only when the owner says “반영”**.

## Hidden cards
연인(06) · 악마(15) · 별(17) · 태양(19) · 심판(20) · 세계(21) have `hidden: true` in `content.js` because the art shows nudity. `deckPool()` excludes them and every draw path uses it.
To re-enable one: upload clothed art under a **new filename** (e.g. `cards/06-v2.jpg` — `/cards` is cached for a week, so overwriting in place keeps old art on devices), point `img` at it, delete `hidden: true`, remove it from the hidden list in `tests/content.test.js`, run the tests.

## Invariants — do not break
- Privacy: a reload or 처음부터/처음 화면 must never bring back the previous student. No sessionStorage/history state restore — the one exception is the text-free `sessionStorage` flag `maum_tarot_help` (help card up), which makes a reload show the help card again (with a blank state) until the teacher long-press; never store student-written text in localStorage.
- `clearDraw()` bumps `gen` and cancels timers. Draw-step animations use `later(fn, ms)` (dropped if `gen` changed; also cancelled when leaving step 2). Any async work (AI calls) must capture `gen` first and drop its result if `gen` changed.
- Navigation (`next/prev/restart/redraw/start/drawBack/toReading`) is debounced by `navOk()` (450 ms) so double taps can't skip steps.
- Every user-controlled string that reaches `innerHTML` goes through `esc()`; AI and student text goes in with `textContent` (the note textarea is filled with `.value`).
- Safety first: `Safety.check` runs on the note when pressing 카드 펼치기 (`next()` at step 1) and on every chat question **before** the question-limit check and before any network call. A hit (or an AI reply with `[도움필요]`, or server reason `SAFETY`) calls `raiseFlag(cat, from)`: sets `state.flag={cat,from}`, logs only a timestamp to localStorage `maum_tarot_flags` (`{log:[ms…], seen:ms}`), and `render()` shows `helpScreen()` instead of any step. While `state.flag` is set, `next/prev/restart/redraw/start/ask` do nothing and the menu hides 처음 화면. A 1.5 s long-press on `#teach` (`holdBtn`) → `teacherOk()` → `endFlag(false)` resume (clears a flagged note) or `endFlag(true)` restart; `endFlag` clears `maum_tarot_help`. `teacherOk()` does **not** mark the log seen (a student can hold that button too): `body.flagged` (red crest) = flag active or unseen log entries, and only a 1.5 s long-press on Settings → 도움 안내 기록 → `#seeflags` '확인했어요' (`holdSee()` → `seeFlags()`) sets `seen`; explained only in 도움말.
- Privacy: the note is never echoed (makeReading only checks whether it exists), never sent to the AI, never stored. Questions are `Safety.redact`ed before they are shown and sent. The chat shows a fixed notice under the divider and source tags on bubbles (`src`: `ai` AI 답변 / `local` 준비된 답변 / `info` 안내).
- Korean particles: never glue a fixed particle to a variable (`${x}가`). Use `Reading.josa(x,"이","가")` (a test scans for this). Card names are shown as-is (no display labels); new student copy is 해요체.
- Reading copy: `makeReading()` in index.html only passes `hasNote:state.note?true:false` to `Reading.make`; reading.js never sees the note or global `state`. The "미래를 맞히는 게 아니에요" notice sits above the reading (`.notice.top`). The scent screen shows which card each scent came from (`scentFrom`) and the smell-safety lines.
- AI calls (device key, raw `fetch`, no SDK): `claudeFetch(key, model, body, signal)` adds model/thinking/fallbacks/headers and the Sonnet 400-retry. `callClaude(key, model, {system, messages, max_tokens}, ctl?)` = one non-streamed answer (15 s) → `{ok, text, stop, error}` (연결 확인 sends one `안녕` with max_tokens 10; extras). `streamClaude(key, model, {system, messages, max_tokens}, onText, ctl)` = the one SSE helper for the reading and chat: `getReader()` + `TextDecoder`, events split on blank lines, handles `content_block_delta/text_delta`, `message_delta.stop_reason`, `error`, `message_stop`, ignores ping/other blocks (incl. Sonnet's `fallback` block); `onText(fullTextSoFar)` returning `false` aborts; no first text in `FIRST_MS` 8 s or over `TOTAL_MS` 30 s → abort; → `{ok, text, stop, why}` (`ok` = got `message_stop`; callers check `stop`). Every per-student request uses `aiCtl()`; `clearDraw()` calls `stopAi()` to abort them all. Callers check `stop_reason` themselves: reading needs `end_turn`; chat accepts `end_turn`/`max_tokens`; refusal is always a failure.
- AI reading (`aiOn()` = device key saved and not `cfg.aiOff`; otherwise the template path is exactly as before, with no tag): `afterPick()` on the 3rd card calls `makeReading()` (template `state.readHtml`, plain `state.reading`, `state.scents`) and `startAiReading()`; `toReading()` only fills in if missing. `aiRead = {g, text, st:'run'|'ok'|'fail'}` (gen-guarded); `paintReading()` renders `#reading` from it (typing `.aiwait` until the first `■`, then `<p><b>title</b><br>text</p>` updated in place; titles come from local data via `readTitle(i)`, not from the AI; `notLiteral` is appended to a finished 죽음/탑 section) or from `state.readHtml`; `#readsrc` shows 'AI가 쓴 풀이' / '준비된 풀이' (empty when AI isn't used). Success = `end_turn` + `readingOk` + no `badReading` (or the 30 s cut with all 4 sections and a finished last sentence) → `state.reading` = AI plain text (chat context) and `startExtras()`. Anything else → template + '준비된 풀이'; `[도움필요]` → `raiseFlag('ai','ai')`. While streaming, `markerHold()` keeps a trailing partial marker ('[', '[도' …) or a leading bracketless '도움필요' off the screen (reading and chat). `setAiOff(true)` calls `stopAi()`, drops `aiRead`/`extras`, resets `state.reading` to the template and re-renders (steps ≥3); `startExtras()` and the end of `startAiReading()` (`a!==aiRead`) re-check, so nothing AI-written or paid is sent after AI is turned off. `chatCtx()` sends the AI text on screen while the reading still streams (never the hidden template). Requests carry only color/topic/cards — never the note (a test scans `startAiReading`…`추가 질문` for `note`).
- Extras: one `callClaude` after a successful reading (`EXTRAS_SYSTEM`, max_tokens 500, must be `end_turn`); `extras = {g, scents, questions}`. The AI never picks scents (`pickScents()` does; unknown names are dropped). `scentCard()` shows the AI reason (`.why`, small 'AI' tag) instead of the description and the AI smell question (`.sq`), else the description + `SMELL_QUESTIONS[i]`. `chipList()`/`paintChips()` = AI questions first, padded with `CHAT_CHIPS`, minus already-asked ones, max 3, hidden once `askCount>=ASK_LIMIT`; a chip calls `ask(text)` (sends at once; same safety check and limit).
- Chat: `ask(preset?)` streams device-key answers into the pending bubble (`liveBubble()`, text node updated in place, `#chatlog[aria-busy]` while streaming; `markerHold()` holds back a partial `[도움필요]`; a marker aborts and raises the flag). Failure → server path → local answer, as before. `cfg.aiOff` (Settings → AI 기능 끄기) hides the chat and skips every AI call (also the server path of a question already in flight). Bubbles strip markdown symbols (`noMd`). The '남은 질문 N개' hint shows only where AI can answer (device key, or the server once answered `OK` — `serverAi`); on keyless devices it is empty because local answers never count. The chat greeting doesn't call itself an AI. `chatHistory` holds only AI-answered `{role,content}` pairs; local answers are not added. `askCount` counts **only AI-answered questions** (incremented after an AI answer arrives; prepared/local answers don't use up a question) and is per student: `clearDraw()` keeps it, only `restart()` resets it. Local answers come from `Reading.localAnswer(q, <count of earlier src:'local' entries in chatLog>, {draw, topic, scents})` (never the note). A failed AI path shows `AI_DOWN` once (NO_KEY stays silent).

- Layout / fit: only ≥900px wide is scaled to the viewport (`fit()`, `refit()` = rAF-debounced; ResizeObserver on `.shell`). 701–899px (portrait tablets) and phones are never scaled — they get the bigger fonts of the `@media(min-width:701px)` block and scroll normally. `fit()` never scales below 0.8, and never so far that `.reading p` / `.bubble` drop under 15px effective. `.shell` must stay `vertical-align:top` (otherwise the negative margin doesn't remove the freed space). `fit()` is skipped while `picking`; `afterPick()` calls `refit()`. Draw slots always hold a card-sized placeholder (`.slot .ph`) so filling a slot never changes the height. Short wide screens (`min-width:900px and max-height:900px`) use smaller cards (`--cardw/--cardh` on `.s-draw`) and a shorter room; at ≥900 slots and the nav sit side by side (`.drawfoot`).
- Card fan: `geom()` reads `--cardw/--cardh` and the fan's `bottom`, shrinks spread+rotation until the outermost card's top corner is inside the room, and computes `--lift` (how far `.card.chosen` rises, used by `.card.chosen`/`.card.done` CSS) from the room height so the revealed card is never clipped. During a reveal `.tarot-room.revealing` moves `.roomhead` (status + counter) to the bottom strip. `pick()` waits for the front image's `decode()` (max 1.5 s, gen-guarded) before flipping; `newDeck()` preloads the deck images (`warmDeck`) during the shuffle. Picked cards get `tabindex=-1` + `aria-hidden`; the room's scroll is pinned to 0 (keyboard focus would scroll it).
- Dialogs: `sheet(html)` = `role=dialog aria-modal`, `.app` is `inert` while open, clicks in the first `SHEET_GUARD` 350 ms after a sheet opens are swallowed (capture listener + backdrop check — a double-click's second click must not press a control in the new sheet or close it; tests wait `sheetWait()` 400 ms before clicking inside a fresh sheet), the inner gold frame is an inset `box-shadow` (stays put while the sheet scrolls), focus goes to the sheet box and returns to the opener on close, Tab wraps, Escape closes. Inputs inside mark the sheet dirty (`markDirty()`; controls that save instantly carry `data-instant`). A dirty sheet ignores backdrop clicks and `closeSheet()` asks first; `closeSheet(true)` closes without asking (after saving, or when `raiseFlag` takes over). Settings: 저장 (`applyKey`) saves a typed key and closes; 연결 확인/키 삭제 sit under the key field. Scent list: 기본값으로 only refills the editor; nothing is stored until 저장, and a list equal to `DEFAULT_SCENTS` is stored as `null`.
- Destructive student actions ask first: `redraw()` always, `restart()` when `hasWork()` (step ≥3 or chat); `restart(true)` skips it (teacher's 처음부터 on the help card). The reading nav keeps the left slot empty (`.navgap`) — 다시 뽑기 sits in `.mid` next to 향기 추천.
- Accessibility: after `render()`, `refocus()` moves focus to the new step's `h2` (the reading plaque is an `h2`) or, on a same-step re-render, to the selected row; never while a sheet is open. Rows carry `aria-pressed`; `#status` is `aria-live=polite`; `#chatlog` is `role=log`. Chat Enter ignores IME composition (`isComposing`/229). Small gold text uses `--gold-text` (#7d6326, ≥4.5:1), never `--gold`.
- Fun (stage 6, all in the '재미 요소' block of the inline script, above the first `render()`): topbar `.tools` = `#fsbtn` 가 (글씨 크게) · `#sndbtn` 🔈/🔇 · ?
